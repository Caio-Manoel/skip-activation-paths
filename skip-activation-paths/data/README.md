# Synthetic dataset

> **All behavioral data in this analysis is synthetic and is used solely to demonstrate the analytical methodology. It does not represent actual Skip users or performance.**

Generated by [`scripts/generate_synthetic_data.py`](../scripts/generate_synthetic_data.py) (seed `20261007`, ~20 s). Event names follow the *proposed* schema in [docs/event-tracking-plan.md](../docs/event-tracking-plan.md); they are not Skip's real tracking.

## Files

| File | Grain | Rows | Notes |
|---|---|---|---|
| `users.csv` | user | 17,660 | 17,630 real-like users + 30 internal/QA accounts (`is_test_account = true`) |
| `events.csv` | event | ~600k | Includes deliberate data-quality problems (below) |
| `subscriptions.csv` | subscription | ~1.2k | Plus/Pro, monthly/yearly, refunds within 14 days, cancellations |
| `drawing_calendar.csv` | date | 26 | Synthetic live-drawing days (Tue/Thu). **Not** Skip's real schedule |

Window: signups 2026-06-01 → 2026-07-30 (60 days); events observed through 2026-08-29 (90 days). Cohorts after 2026-07-26 are right-censored for D30.

## How the data is generated

### 1. Users
- **Signups/day:** ~255 with mild growth, a weekend dip (−22%), a holiday dip on 4 July, and a **paid-social campaign 6–19 July** that adds ~115 extra signups/day. Cohort sizes therefore differ.
- **Acquisition channel** → **initial intent**: each channel has its own intent mix (e.g., `grant_listings` is 78% funding; the campaign is 60% create).
- **Latent engagement propensity `z` ~ Normal(μ_channel, 1).** It is *never written to the files*. It raises return probability, feature breadth, success at each step and paid conversion simultaneously — the source of the selection bias the analysis has to handle. Users with `z > 1.9` are **power users** (extra sessions).
- 30% of users have a **secondary intent**; 65% answer an onboarding `intent_selected` question, which disagrees with their landing intent ~10% of the time.

### 2. Behavior
- **Day 0:** signup → (unless a **one-session bouncer**, ~12%, more in the campaign) open the primary feature → attempt the intent's outcome. Higher-`z` users are more likely to explore a second feature (**feature-selection bias**).
- **Each later day:** a user returns with probability `sigmoid(logit)` where

  ```
  logit = α[intent] − 0.62·ln(1+day) + 0.9·z
          + β_value[intent]·(reached value yet)
          + 0.12·(value in 2+ features)            ← small true cross-feature effect
          + 0.25·(bridged Analyze → Cofounder)      ← modest true bridge effect
          + 3.4·(drawing day AND drawing-engaged)   ← event-driven returns
          − 0.25·(weekend) + 1.0·(power user)
  ```
- **Drawing-engaged users** (62% of funding users, 12% of others) often return on drawing days only to enter (`instant_grant_entered`) and leave — activity without tool use.
- **Grant incentive:** funding users are pulled toward website/business-plan completions (mirroring the public note that grant amounts depend on what the business has completed). These completions have **zero** causal effect on retention in this world.
- **Analyze → Cofounder:** after a successful analysis, a user continues into Cofounder with probability `sigmoid(−2 + 0.5·z)` — self-selection by design.

### 3. Monetization
Paid conversion probability depends on `z`, whether value was reached, intent (funding lowest, presence/create highest) and active days. Tier, billing period and refunds (more likely for low-`z` users) are drawn per subscriber.

### 4. Data-quality problems injected on purpose
| Problem | Size |
|---|---|
| Retry duplicates (same `event_id`) | ~0.5% of rows |
| Missing `session_id` on Android | ~1.2% of Android events |
| Device clock skew (event before signup) | ~0.3% of mobile events |
| Late-arriving mobile events (offline queue up to 72h) | ~5% of mobile events |
| **iOS tracking break**: `analysis_completed` not emitted 14–18 July | all iOS analyses in that window |
| Internal/QA accounts with implausible volume | 30 users, ~5% of events |

### 5. Ground truth
The true causal parameters are written to `scripts/ground_truth.json`, outside `data/`, so the analysis never reads them while estimating. They are used only afterwards to check which observational conclusions were right.

| Hypothesis | Designed to… |
|---|---|
| H1 intent-dependent activation | be **mixed**: universal metric predicts similarly, but miscounts some intents |
| H2 complete > explore | be **supported** (true effect is large) |
| H3 cross-feature | **look supported but be mostly selection** (true effect small) |
| H4 Analyze → Cofounder | be **real but much smaller than it looks** |
| H5 funding retains differently | be **supported** (drawing-driven activity) |
| H6 speed > breadth | be **unsupported** (speed has no true effect) |
| July cohort "retention drop" | **disappear after segmentation** (campaign mix shift) |

A second world with randomized assignment to the Analyze → Cofounder bridge is generated by `analysis/simulated_experiment_b.py` (`EXPERIMENT_B=randomized`).
